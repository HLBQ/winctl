# winctl 窗口控制

> **把不听话的窗口，收进你的手掌心。**

有些程序一旦跑起来，就不太把桌面规矩放在眼里：无边框铺满整屏、一失焦就疯狂往最前面挤、
隔几秒自己弹回屏幕中央、窗口大小说改就改、点关闭还装听不见。

winctl 做的事很简单——**给这些窗口套上一根缰绳**。你想让它靠前，它就在最前；
你想让它安静待在角落里，它连抢的资格都没有。整个过程不需要改那个程序一行代码。

---

## 一、你是不是也遇到过这些情况

- 教室软件的学生端一上来就**无边框霸屏**，把整个桌面挡得严严实实，想切出去处理点别的事都难。
- 某个工具窗口**一失去焦点就"闪"**，疯狂申请到最前面，你正在打字的输入框被它反复抢走。
- 窗口**自己会跑**：你把它拖到角落，半秒后它又弹回屏幕正中。
- 你只想把窗口**缩小一点**，程序却不肯配合——画面还是那么大，右下角直接被切成两半。
- 有些程序**关不掉**，点叉、按 Alt+F4 都当没看见。
- 你想把某个程序塞进自己的工具界面里，又不想重写它的显示逻辑。

这些事，winctl 都能接。

---

## 二、它能做什么

每一项都是**双向开关**：打开是一种效果，关掉是相反的效果，不是"只能管一头"。

| 能力 | 打开时 | 关闭时 |
|---|---|---|
| **置顶控制** | 强制它在所有窗口之上 | **吞掉它所有的置顶请求**，想抢也抢不上去 |
| **全屏控制** | 强制它无边框铺满屏幕 | 强制退出全屏，**没有标题栏就给你补一个** |
| **移动锁** | 位置彻底钉死，谁也搬不动 | 不干预，窗口自由移动 |
| **锁定大小** | 尺寸不再被程序改来改去 | 不干预 |
| **冻结窗口** | 置顶 / 位置 / 大小 / 全屏一起定格，**连最大化、最小化都不许**，别的程序强改也会被按回去 | 全部放开 |
| **内容缩放** | 窗口变小，**画面等比缩放到窗口里**，一个像素都不裁 | 内容按原样 1:1 画 |
| **焦点模拟** | 它以为"我本来就是前台"，**不再反复抢焦点、不再闪** | 不干预 |
| **显示重映射** | 把它的完整画面搬到另一个窗口里显示，**键鼠操作照样有效** | 关闭，恢复原状 |
| **一键窗口化** | 无边框霸屏 + 狂抢置顶 + 关不掉，一条命令变回**带标题栏、可拖可缩放的普通窗口** | — |
| **跳至顶层** | 帮它露个脸、跳到最前，**只此一次，不留置顶后遗症** | — |
| **强制关闭** | 连拒绝关闭的程序也能结束 | — |
| **多窗口接管** | 一个程序的所有窗口一起管，各自记住自己的位置 | 只管主窗口 |
| **自动续管** | 窗口被销毁又重建、程序中途没窗口，规则都会**继续生效** | — |

还有几样顺手的：

- **窗口里的控制面板**：贴在目标窗口顶部的一条小工具条，**平时完全隐形**，鼠标移上去才出现；
  它不改变目标窗口尺寸，不挤占画面。
- **全局热键**：`Ctrl+Alt+T` 置顶、`Ctrl+Alt+F` 全屏、`Ctrl+Alt+L` 移动锁、`Ctrl+Alt+H` 显示/隐藏面板。
- **图形控制台**：列表里点一下就能附加、注入、强制关闭、重启并注入、卸载还原。
- **32 / 64 位通吃**：不用自己判断目标位数，程序会自动交给对应版本处理。

## 三、怎么用

### 图形界面：`wctl_gui.exe`

打开就是一份进程名单，选中一个，剩下的都是点按钮：

- **附加并注入**：目标已经在跑，直接接管
- **启动并注入**：没在跑，帮你拉起来并接管
- **重启并注入**：先关掉再按原路径启动并接管，一步到位
- **强制关闭** / **卸载还原**
- 右侧一排开关：置顶、全屏、移动锁、锁定大小、锁定窗口状态、显示面板、多窗口、
  远端画面等比缩放、焦点模拟、显示重映射、位置模拟……
- 下方日志区会打印实际执行的完整命令，**所见即所得，也能直接复制去命令行跑**

名单可以自定义（`bin\blacklist.txt`）。不在运行中的程序也会列出来，方便你"一键启动并注入"。

### 命令行：`winctl.exe`

一句话接管一个程序：

```cmd
:: 让它变成带标题栏、可拖可缩放的普通窗口，并且锁住位置
bin\winctl.exe --attach xxx.exe --windowed --lockmove=user

:: 已经跑起来的目标，直接改开关
bin\winctl.exe --set xxx.exe topmost=off fullscreen=off lockmove=on

:: 看看现在到底是什么状态
bin\winctl.exe --status xxx.exe

:: 不要了，全部还原
bin\winctl.exe --detach xxx.exe

:: 拒绝关闭的程序，强制结束
bin\winctl.exe --kill xxx.exe
```

目标既可以写**进程名**（`xxx.exe` 或 `xxx` 都行），也可以写 **PID**。

## 四、几条命令，对应几个真实场景

**① 教室软件学生端：无边框霸屏、狂抢置顶、关不掉**

```cmd
bin\winctl32.exe --attach xxx.exe --windowed
```

一条命令三步到位：拆掉全屏霸屏、把标题栏补回来、摆成工作区 72% 的窗口并锁住位置。
它的置顶请求会被**在它自己进程内**直接吞掉，所以你连闪烁都看不到。

> 实测：注入前 95 次采样里 95 次处于置顶、95 次没有标题栏；注入后 157 次采样 **全部为 0**，
> 而期间程序自己还在不停地发请求——不是它变乖了，是请求被按住了。

**② 远程桌面 / 屏幕广播：窗口变小了，画面右下角没了**

这类程序把远端画面按固定分辨率 1:1 画进一个子窗口，窗口再小它也照旧画那么大。
winctl 的做法是：**让它照旧画完整的一帧，我们再把整幅画面等比缩放贴进窗口**。
窗口小了、画面全在，不会出现"只看到左上角"。

```cmd
bin\winctl.exe --attach xxx.exe --windowed
```

鼠标坐标会**反向换算**，所以缩放之后你点右下角，点到的仍然是画面右下角。
如果目标压根不是用常规方式绘制（比如 DirectX），它会**自动退回"保持原始内容尺寸"**
——把窗口恢复成能完整显示内容的大小，绝不会把你扔在一个被裁掉的小窗口里。

**③ 程序自己乱跑、乱改尺寸**

```cmd
bin\winctl.exe --attach xxx.exe --lockmove=user --locksize=on
```

`--lockmove=user` 的意思是：**程序自己不许搬窗口，但你可以随便拖**。
想连你也拖不动，就用 `--lockmove=on`。

**④ 窗口一直闪、一直抢焦点**

```cmd
bin\winctl.exe --attach xxx.exe --focus=on
```

它问"我是不是前台"，我们回答"是"。它想抢前台，我们直接把动作吞掉并告诉它"成功了"。
于是它安安静静，你也安安静静。

**⑤ 想把一个程序"搬进"自己的界面里**

```cmd
bin\winctl.exe --attach xxx.exe --remap=on
```

源窗口以原始尺寸待在屏幕外（照常运行、照常收帧），桌面上另开一个窗口显示它的完整画面。
鼠标、滚轮、键盘都会换算坐标后投递给源窗口，用起来和原程序一样。

**⑥ 只想让它老实待在一个固定位置**

```cmd
bin\winctl.exe --attach xxx.exe --freeze=on
```

把**你按下开关那一刻**的置顶、位置、大小、全屏状态全部固化，之后谁也改不动，
连最小化、最大化、Win+D 都动不了它。想解除就 `--freeze=off`。

## 五、它适合接管什么样的程序

- 教室 / 培训类控制软件的学生端、教师端
- 远程桌面、屏幕广播、监控画面
- 各种"窗口化以后画面被裁"的固定分辨率程序
- 有看门狗、爱抢置顶、爱自己挪位置的桌面工具
- 关不掉的弹窗、启动器、守候进程

**不适合**的：带内核级反作弊保护的游戏、PPL 受保护进程、完全不用 Windows 窗口机制
（DirectX 独占全屏且不处理窗口消息）的程序——这些从系统层面就不允许外部接管。

## 六、产物

| 文件 | 说明 |
|---|---|
| `bin\winctl.exe` | 命令行入口（64 位目标） |
| `bin\winctl32.exe` | 命令行入口（32 位目标，如 32 位学生端） |
| `bin\winctl_hook.dll` / `winctl_hook32.dll` | 接管目标窗口时载入目标进程的部分 |
| `bin\wctl_gui.exe` | 图形控制台 |
| `bin\remap_host.exe` | 演示 / 验证用的示例目标程序 |

构建：

```cmd
build.cmd
```

## 七、一句话说明

它不修改你的程序，也不改系统文件；它只是**在目标程序自己的进程里，替你把那些不合理的要求
礼貌地挡回去**，在你不要它的时候完整还原。

所有规则都是**可逆**的——`--detach` 一执行，窗口就回到接管前的样子。
